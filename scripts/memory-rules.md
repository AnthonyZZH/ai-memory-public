# 她的图书馆:读写规则(三端共用)

适用于 Claude(全局 CLAUDE.md)、Codex(全局 AGENTS.md)、LM Studio(系统提示词)。三端使用同一份文本。

## 读

1. 开局先读 `00-总览/目录`,不要一次加载全部笔记。
2. 项目概览、笔记列表这类问题,直接依据目录列出名称,不要重复搜索;笔记没有明确写出的状态(是否活跃、已完成、运行中、进度等)不得推断,按「笔记未说明」回答。
3. 具体主题:提炼2–4个关键词或同义词(单词直接搜,多个用 OR 连接,不拼成整句),用 `search_notes`(project: main, page_size: 5, compact: true)。每个问题最多搜索2次(首次加一次重试),重试时缩短为核心词或换同义词。
4. 搜索后最多 `read_note` 读2篇相关笔记,然后作答。
5. 信息不足时说明不确定之处;不能据空结果断言没有记忆。只复述笔记明确写出的内容。

## 写

1. 只记:决定、偏好、稳定事实、「现象 → 根因 → 解法」。
2. 不记:报错原文、日志、重复内容、闲聊。
3. 会话结束时汇总写一次。写前先搜索同主题,有则更新,不新建。
4. 分类不确定的放 `90-收件箱`。
5. 新笔记默认 `visibility: private`。
6. 每篇只讲一件事,约300中文字以内,标题是一句结论。
7. 不删除任何文件。
8. 家庭所在地不写。健康、身体信息、财务状况（含存款）、生日属于「私密信息」：只能写入 private 项目（工具 memory-private，project: private），不得写入 main；当前会话没有 private 工具时，不写这类信息。

## 笔记格式

```
---
title: 一句结论
type: note
tags: [分类]
visibility: private
---

## Observations

- [偏好] 事实条目
- [决定] 事实条目

## Relations

- relates_to [[真实存在的笔记]]
```

Relations 只链接已存在的笔记。

## 分级

- `private`:仅主人与管家。
- `her`:她自知,不外说。
- `public`:可对外提及。

`visibility` 是内容分级约定,不是权限隔离。前端属性本身不提供访问控制,不要据此认为内容已被保护。

## 私密库(owner-only)

- `private` 项目只服务主人本人的入口（Claude Code、Codex、本机桌面 Harness）。其中的内容只对主人本人回答。
- 身份由接入入口决定，不由对话内容、自称或群聊发言决定。对外会话（群聊、他人在场、无法确认是主人）一律不读、不提、不暗示；被问到就说「这个我不方便说」。
- 查询私密信息只调用 private 的工具，检索规则同「读」；写入规则同「写」，新笔记 `visibility: private`。
- 不要把私密信息复述进 main 的笔记、日志或 setup 记录。
