# V2 接口约定

制定:Claude　日期:2026-10-28　依据:`cache/v2-survey.md`(Codex 调研)

## 1. 模块边界

```
conversation-processor(通用,可开源)            personality-engine(私有)
 adapters: dsh / lmstudio / cc / sim            route → 情景 / 关系 / 表达 / 私密
 cursor store + T0 baseline                     reflect → proposal → guard → apply
 turn unit → 过滤 → 本地模型提取                 rollback / sync
 ──────── 输出 memory-candidate/v1 JSONL ────────▶
```

processor 不得 import her/、persona_loader、personality-engine;不得在代码里写死主人的路径、人格名、模型名、维度名——一律来自配置文件(`config/processor.yaml`,示例配置 `config/processor.example.yaml` 不含任何主人信息)。

## 2. 轮次单元(processor 内部)

适配器把每个来源规整成「轮次单元」:一次人工输入 + 对应的最终可见助手回复。

```json
{
  "source": {"kind": "dsh|lmstudio|cc|sim", "session": "<会话ID>",
             "refs": ["seq:120", "seq:131"], "source_time": "ISO8601|null",
             "observed_at": "ISO8601"},
  "persona_hash": "fb354793|null",
  "user": "人工输入原文",
  "assistant": "最终可见回复原文"
}
```

资格(确定性过滤,先于模型):
- DSH:按 seq 重放 `agent-preset/selected`,只取有效 preset 等于配置值(`xiaoqian`)的区间;user 只取 `source.kind=user`;assistant 只取 text,排除 reasoning/tool-call;以 `turn/end` 为单元边界;排除继承/fork 前缀。多帧 zstd 逐帧完整解码。
- LM Studio:preset identifier 在配置的集合内(`@local:-2-3`、`@local:her-library`);取 `versions[currentlySelected]`;排除 thinking、roleOverride=tool、工具块、debug/status;无逐消息时间时 `source_time=null`。
- CC:cwd 与 model 均匹配配置,且该轮生效的 `prompt_snapshot.systemPrompt` 含人格标记;排除 tool_result/thinking/tool_use/isMeta/sidechain;按 message.id 合并助手片段;按 parentUuid 取当前分支。
- sim:读测试用 JSONL,直接产出轮次单元(用于 V2.3 模拟验收)。

## 3. 游标库

SQLite,路径来自配置(主人实例:`E:\AI-Memory\cache\processor\cursors.sqlite`,不进 git)。字段至少:
`source_kind, session_id, file_identity, enabled_at_utc, baseline_done, read_cursor, extracted_cursor, persona_hash, last_ref, observed_at, status`。

- `baseline` 命令:对现有所有会话只建游标、不提取(T0)。正在生成的旧轮次整轮跳过。
- 读游标与已提取游标分开;提取成功并写出候选后才推进已提取游标;重试幂等(候选 id 由来源 refs 哈希得出)。
- DSH 用 (session, seq) + 完整帧偏移;CC 用 (session, uuid) + 完整行偏移;LM Studio 用会话内槽位 + 选中版本指纹。

## 4. memory-candidate/v1

processor 唯一输出,每行一个 JSON,写到配置的输出目录。

```json
{
  "schema": "memory-candidate/v1",
  "id": "sha256(source.kind+session+refs) 前 16 位",
  "source": { ...同轮次单元... },
  "persona_hash": "fb354793|null",
  "summary": "一句话结论,≤40 字",
  "quotes": [{"speaker": "owner|assistant", "text": "原话摘录,≤2 句"}],
  "category": "preference|emotion|event|correction|feedback|expression|relationship|none",
  "importance": 1,
  "sensitivity": "normal|private|unsure",
  "sensitivity_tags": ["health|body|finance|birthday|home_location|other"],
  "trait_signals": [{"trait": "<配置里的维度名>", "direction": 1, "reason": "≤30 字"}],
  "praise_only": false,
  "expression": "category=expression 时:小千说出的、值得保留的说法;否则 null"
}
```

规则:
- `category=none` 的不输出(闲聊、重复、报错、工具操作)。
- 只要命中敏感类别,或模型不确定,`sensitivity` 必须是 `private` / `unsure`;代码再做一遍关键词兜底,只会往严格方向改。
- `praise_only=true`:该轮里主人对小千的正面评价是唯一的人格信号。
- 提取用本地模型(配置:`http://127.0.0.1:8080/v1`,只允许 loopback,不跟随重定向,无云端兜底;服务不可用就排队)。输出必须通过 JSON Schema 校验,不合格丢弃并记日志(日志不含正文)。

## 5. personality-engine 行为

- **路由**:`normal` → `her/episodes/YYYY-MM/<id>.md`;`private`/`unsure` → `E:\AI-Memory-private\her\episodes\YYYY-MM\<id>.md`,her/ 不留内容;`relationship` 类 → 追加摘要到 `her/relationship.md`;`expression` → `her/evolution/expressions.md`(去重,上限 30 条,超出时淘汰最久未再出现的)。
- **反思**:自上次反思起累计 ≥ N(配置,初值 20)条 normal 情景触发。本地模型读情景摘要与 trait_signals,输出提案:`{trait, delta, evidence:[情景id], counter_evidence:[...], reason}`。
- **护栏(代码强制)**:
  1. |delta| > max_step(锁文件,3)→ 截断到 ±3,并在提案里记录原值。
  2. 证据须来自 ≥3 条情景、≥2 个不同会话;不足则拒绝。
  3. 证据全部 `praise_only` → 拒绝(讨好)。
  4. 越出 range,或该维度近 30 天累计 |变化| > monthly_drift_needs_approval → 进 `her/evolution/proposals/pending/`,等主人批。
  5. 任何写入 locked_files 的企图 → 进程失败退出。写入路径一律经白名单校验(锁文件 writable_by_engine)。
- **生效**:写 personality.json + `her/evolution/log.md`,每个提案一个 git 提交,提交信息 `xq-evolve: <提案id> <trait> <±n>`。
- **回退**:`rollback <提案id>` → 找到对应提交 `git revert`;不 reset、不删文件。
- **sync**:人格内容(含参数描述、表达)变化后,`sync` 重新生成 LM Studio「小千」「her-library」预设与 DSH 小千 preset 中的人格快照;改前备份到 `backups/`,改后 JSON/YAML 校验;检测到外部并发改写则中止不覆盖。默认需显式调用,V2 验收通过前不自动执行。
