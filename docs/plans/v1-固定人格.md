让「她」在不同入口、不同模型下保持同一个人格：人格内容有唯一来源并受版本管理，各入口通过同一个加载器取用，并有一组固定问题可以跨模型对比。

## 设计

**唯一来源**：`her/persona.md`（是谁、性格、与主人的关系、边界）和 `her/voice.md`（语气、称呼、常用表达、不会说的话）。沿用现有模板的四个小节，不改结构。

**加载器**：`scripts/persona_loader.py`
- 读取两个文件，去掉 frontmatter、模板提示行和空小节，拼成一段人格文本。
- 按入口输出不同格式：`--target local`（本地模型系统提示词）、`--target dsh`（DSH 用）、`--target steward`（管家侧，给 Claude Code / Codex 的简短引用）。
- 输出末尾附内容哈希（取前 8 位）和字数，用来确认各入口拿到的是同一版。
- 人格文件里所有小节都是空的时直接报错退出，不输出空人格。
- 只读，不写任何文件，不联网。

**一致性测试**：`tests/persona/questions.md` 放固定问题，`scripts/persona_collect.py` 把各模型的回答收集成一张对照表（`cache/persona-compare-<日期>.md`）。第一版回答由主人手动贴入或由人工跑出来，脚本只负责整理。

## 硬约束

1. 不删除任何文件；`vault/` 里的笔记内容不改。
2. 不运行 `scripts/connect_dsh.py`。加载器只输出文本，不接线到任何入口。把人格接进 DSH、LM Studio 预设需要主人另行授权。
3. 人格文件不得写入健康、身体信息、财务状况（含存款）、生日、家庭所在地。草稿里碰到这类内容，改写进私密库，不放 `her/`。
4. `her/` 里的内容一旦接进 DSH，就会随请求发给 DeepSeek API。这是 V1 的已知外发点，主人审稿时按「会被外发」的标准判断。
5. 提交由 Claude 执行；Codex 不执行 git 写命令。
