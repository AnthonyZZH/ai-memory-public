## 流程

1. **采集**:按水位线增量读取三个入口的新对话(格式见 Codex 调研 `cache/v2-survey.md`),只取小千人格的会话,过滤工具调用和思考过程。
2. **提取情景**(本地模型):判断哪些互动值得记——主人表达的偏好/情绪/重要事件、小千被纠正、一次特别成功或失败的回应、新出现的说法。闲聊、重复、报错原文不记(沿用图书馆写规则)。每条情景附:时间、来源会话、原话摘录(≤2 句)、类别、涉及的人格维度。
3. **私密分流**:命中私密类别的情景只写私密库,her/ 只留「有一条私密情景」的占位,不含内容。
4. **反思**(本地模型):每攒够 N 条有效情景(初定 N=20)触发一次。输出提案:哪个参数、变多少(≤±3)、支持证据(情景 id)、反对证据。
5. **护栏**(代码强制,不依赖模型自觉):单项 ≤±3;越出 range、单月累计 >10、或涉及锁定文件 → 进待批;仅以「主人夸奖/喜欢」为证据的提案拒绝;引擎写 locked_files 直接失败。
6. **生效**:自动通过的提案写入 personality.json 和 log.md,单独一个 git 提交(提交信息含提案 id)。待批的提案由 Claude 汇总问主人。
7. **回退**:`personality-engine rollback <提案id>` 一条命令还原该次变化(git revert 该提交)。
